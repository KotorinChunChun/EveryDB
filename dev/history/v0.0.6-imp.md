### 0-2. 原因の切り分け

- `shared/source-types.json` は全 Graph データソースを同一 `credentialScope: graph` としている。
- `src/features/credentials/selector.ts` は `list_credentials(scope)` の結果を認証方式・capability で絞り込まず表示する。
- `src-tauri/src/credentials.rs` は Graph delegated プロファイルをデータソース種別に関係なくアクセストークンへ展開する。
- そのため、SharePoint 用 delegated プロファイルを `/groups`、`/users/{UPN}`、Intune 等の非対応 Graph API へ割り当てられ、ネットワーク呼び出し時の 403 まで誤設定を検出できない。
- 現行 Teams ピッカーの `/me/joinedTeams` と `Team.ReadBasic.All` は正しいが、Graph Teams データソース本体は `/groups` を使うため別扱いが必要。
- `docs/guides/microsoft365.md` には表崩れ、誤字、下書き文が残っており、現在差分のままではコミット不可。
- 追加実装前の資格情報scopeは `graph` だけで、UI表示は「Microsoft 365 (Graph)」。既存の全Graphデータソースがこのscopeを参照していた。
- 現在の `graph_onedrive` は app-onlyの `users/{UPN}/drive` と delegatedの `me/drive` を内包するため、個人用を同じtypeへ追加すると既存ロジック変更が必要になる。別typeなら既存分岐を保持できる。
- OAuth実装は任意のtenant文字列をauthorize / token / refresh URLへ使えるため、個人用の新規境界から既存関数へ `consumers` と固定capabilityを渡せる。
- 接続先追加ダイアログの `close()` は保存・キャンセルの双方で呼ばれているが、`#add-dialog { display: flex; }` がユーザーエージェントの `dialog:not([open]) { display: none; }` を上書きしている。このため `open` 属性が消えても表示だけが残り、F5直後にも閉じたダイアログが見える。
- ブラウザ系パス項目のラベルは `forms.ts` に長いファイル名として直接定義されており、表示の重複感は永続データではなくフォーム定義由来である。
- Microsoft Graph のアクセストークンでは、委任権限は `scp`、アプリケーション権限は `roles` claim に入る。既存の資格情報解決処理でアクセストークンを取得できるため、秘密値をフロントへ返さず Rust 側で claim の権限名だけを抽出できる。
- Airtable の `/v0/meta/whoami` が scope を返すのは OAuth access token で、EveryDB が扱う PAT の権限完全取得には使えない。Notion と Box もアプリ設定上の全権限を返す introspection API がないため対象外とする。
- Notionの現行フロントは `database_name` と接続先表示名を通常入力として描画し、`shouldUpdateNotionDisplayName` で手動表示名を保護している。これは完成仕様と逆である。
- Notionの一覧選択ボタンは `#browse-area` に独立配置され、「自動設定」行へ入る参照ボタンはSharePointだけに限定されている。
- 名称取得失敗時の `catch` は保存値を維持する一方で状態を表示していないため、利用者は失敗と未実行を区別できない。
- 420×500の実表示では共通 `.dialog.wide` の固定最小幅560pxがビューポートを140px超過した。最小幅・最大幅を左右16pxのビューポート制約へ変更し、同条件でダイアログ幅388px、内部スクロール高746pxとして収まることを確認した。
- Notion ID欄は従来 `change` のみで名称取得していたため、貼り付け・入力直後に状態が変わらなかった。32桁入力完了後250msのデバウンス取得へ変更した。
- `manager.ts` は `used_by` を `.cm-profile-item` の後ろへ別要素として追加しているため、選択背景・クリック範囲から外れている。
- 権限確認失敗は `var(--danger)` の文字色だけを指定しており、特にナイトテーマの黒背景で判読しづらい。状態バッジとして背景・枠・前景色を同時指定する必要がある。
- Microsoft OAuthコマンドは取得した `access_token` を捨てて `refresh_token` だけ返すため、認可したユーザー情報を保存できない。既に要求している `User.Read` で `/me` を取得すれば、秘密トークンをフロントへ返さずID情報だけを返せる。
- picker系dialogは内容の自然高に任せており、絞り込みやSharePointのstep切替で外寸が変化する。固定 `height` がなく `resize` も未指定であることが原因。
- 固定外寸化後、接続先chooserの `.source-filter-wrap` と SharePoint の `.search` に横方向レイアウト用の `flex: 1` が残り、縦積みされたdialog内で余剰高を占有していた。外寸固定ではなく、固定高コントロールと可変高一覧の責務分離が不足していたことが余白増加の原因。
- `#add-dialog .roles-fieldset` は狭い高さで縮小できる一方、既定の `overflow: visible` により子のツールバーが縮んだ枠外へ描画され得る。fieldsetの最小幅を解除し、グループ内overflowを管理する必要がある。
- 保存済み資格情報一覧は、従来のローカル保存情報表示に加え、フェーズ16から開くたび Microsoft のtoken endpointへ接続して実効権限を確認する。画面の失敗表示はこの追加オンライン診断の結果であり、失敗経路では資格情報を削除・更新していない。

## 2. 要件別・実装方針

### 2-1. Teams 委任ピッカー

- delegated は `/me/joinedTeams`、app-only は既存 `/groups?...Team` を使用する。
- `GraphAuthArgs` はアクセストークンの有無ではなく明示的な認証方式で分岐できる構造へ寄せる。
- `/me/joinedTeams` の `createdDateTime` が `null` になる仕様を UI / ガイドで誤解させない。
- 共有チャネルのホスト Team は結果に含まれないことを説明する。

### 2-2. Graph資格情報の互換性

- source type manifest に許可認証方式・必要 capability を定義する。
- UI は非対応プロファイルを削除せず disabled 表示し、理由と再認可方法を示す。
- Rust は保存・資格情報更新・preview・reload・browse の各境界で同じ互換性を再検証する。
- app-only→delegated 変更時に非対応ソースが参照中なら、資格情報更新を保存前に拒否する。

### 2-3. capability別OAuth

- `sharepoint`: `Sites.Read.All`, `Team.ReadBasic.All`
- `calendar_self`: `Calendars.ReadBasic`
- `onedrive_self`: `Files.Read`
- 共通: `User.Read`, `offline_access`
- authorize と refresh は当該プロファイルに保存した capability から同じscope集合を生成する。
- capability追加時は再認可が必要であることをUIに明示する。

### 2-4. 本人用Outlook

- delegated + `calendar_self` は `/me/events`。
- app-only は `/users/{UPN}/events` とUPN必須を維持する。
- delegated 時はUPN入力を非表示または無効化し、「サインインした本人」と表示する。
- 今回は `calendarView` への変更や繰り返し予定の展開方式変更を行わない。

### 2-5. 本人用OneDrive

- delegated + `onedrive_self` は `me/drive` を起点に既存再帰取得を再利用する。
- app-only は `users/{UPN}/drive` とUPN必須を維持する。
- delegated 時はUPN入力を非表示または無効化し、「サインインした本人」と表示する。

### 2-6. 文書・画像

- 認証方式比較ガイドの表崩れと下書き文を修正する。
- `docs/guides/image/image1.png` は比較ガイドから参照されるため、内容を確認して採用する。
- 未参照の `1785675140681.png` は、機密情報の目視確認ができるまでコミットしない。
- `.cursor/` は今回の変更に含めない。

### 2-7. 組織用・個人用資格情報の分離

- 既存 `graph`、保存済み資格情報、Graph OAuth、互換性判定は変更せず「Microsoft Entra ID（組織）」として扱う。
- `microsoft_account` scopeを追加し、公開フィールドは `client_id`、秘密フィールドは `refresh_token` とする。
- 個人用のauthorize / refreshは既存PKCE実装を利用しつつ、authority `consumers` と `onedrive_self` capabilityを固定する専用コマンド・解決境界から呼ぶ。
- 個人用scopeは組織用Graphソースから参照できず、組織用scopeも個人用ソースから参照できない構造にする。

### 2-8. OneDrive（組織）とOneDrive（個人）

- 既存 `graph_onedrive` の表示名だけ「OneDrive（組織）」へ変更し、connector・UPN・auth分岐を保持する。
- 新規 `microsoft_account_onedrive` は個人用資格情報の一時access tokenだけを受け取り、常に `me/drive` を起点にする。

### 2-9. 個人用OAuthの本番固定クライアントID

- `graph_oauth.rs` に個人用本番クライアントIDを公開定数として置き、認可コマンドとrefresh処理の両方から参照する。
- 個人用credentialは `refresh_token` だけを必須・DPAPI保護対象とし、新規保存では `client_id` を保持しない。
- 既存credentialに別の `client_id` が残る場合は、固定IDでは旧refresh tokenを更新できないため再認可要求を表示し、ネットワーク前にも明示エラーで拒否する。同じレコードを固定IDで再認可・保存するためDB migrationは行わない。
- credential managerからクライアントID入力・取得リンクを削除し、個人OAuth IPCを引数無しにする。
- ガイドは利用者によるEntraアプリ登録手順を削除し、Microsoftログインだけの操作へ同期する。

### 2-10. 接続先追加ダイアログの終了不能とブラウザラベル

- `#add-dialog:not([open]) { display: none; }` を明示し、flex レイアウトとネイティブ dialog の閉状態を両立する。
- 保存・キャンセル・F5初期表示のいずれも `open` 属性が無ければ画面に残らない回帰テストを追加する。
- ブラウザ履歴・ブックマーク・ダウンロード履歴の `path` ラベルを「プロファイル」に統一し、保存済みパス値は変更しない。

### 2-11. 接続先追加一覧の拡大・検索・並び順

- chooser 上部に検索入力とクリアボタンを追加し、入力のたびに表示名・カテゴリ名で絞り込む。
- 検索中もカテゴリ見出しは一致項目があるグループだけ表示し、0件時は空状態を表示する。
- Microsoftカテゴリ内は EntraIDユーザー、EntraIDグループ、EntraIDデバイスを先頭へ集約し、残りは既存順を維持する。
- chooser 専用一覧の最大高さを拡大し、狭い画面では共通 dialog スクロールへフォールバックする。

### 2-12. Microsoft 保存済み資格情報の承認済み権限表示

- Rust側で資格情報IDから実アクセストークンを取得し、JWT payload の `scp`（空白区切り）または `roles`（配列）だけを抽出して返す。アクセストークンやrefresh tokenはIPCへ返さない。
- `graph` は app-only / delegated の既存取得経路を使い、`microsoft_account` は固定client IDの既存refresh経路を使う。refresh tokenがローテーションされた場合は既存処理どおり暗号化保存する。
- 選択一覧と管理一覧は基本情報を先に描画し、権限確認を非同期実行する。確認中・確認済み・確認失敗を各行に表示し、失敗しても選択ボタンは無効化しない。
- Graph互換性による既存の選択禁止は維持し、権限通信失敗による禁止とは分離する。
- Airtable PAT・Notion・Box・DB資格情報は権限照会を呼ばず、既存表示を維持する。
- drive itemのフィールド定義と再帰取得は既存読み取り専用helperを利用するが、既存 `GraphOneDriveConnector` と `one_drive_base` は変更しない。
- 新規フォームにUPNは設けず、利用者へ「サインインした本人」を明示する。

### 2-13. 保存済みトークン一覧の可読性

- `used_by` の名称一覧は `.cm-profile-main` 内へ移し、選択・キーボード操作・削除ボタンとの構造を維持する。
- エラーはテーマトークンで背景・枠・前景色を定義したバッジにし、暗背景へ赤文字だけを置かない。
- 権限claim名はIPC・Rust内部だけに残し、画面上は既存の認証方式用語へ翻訳する。

### 2-14. Microsoft認可主体の記録

- OAuth直後のaccess tokenで Graph `/me?$select=id,displayName,mail,userPrincipalName` を取得する。
- IPCは `refresh_token` に加え `authorized_account_id` と `authorized_account_name` だけを返し、access tokenは返さない。
- credential fieldsへ2項目を非秘密情報として保存し、認可状態に `表示ID（ID: ...）` を表示する。
- 旧資格情報は互換性を壊さず「認可済み（認可アカウント未記録）」と表示する。

### 2-15. 選択系ダイアログの安定した外寸

- connection chooser、単純picker、Excel/DB picker、SharePoint picker、資格情報pickerへ共通クラスを付ける。
- 共通クラスは既定の幅・高さ、`resize: both`、`overflow: auto`、ビューポート基準の最大幅・最大高を持つ。
- 一覧自体は残り領域をスクロールし、絞り込み0件やstep切替でもdialog外寸を変更しない。

### 2-16. 固定外寸ダイアログの内部レイアウト回帰修正

- connection chooserの検索ラッパー、SharePoint pickerのタブ・検索欄を `flex: none` とし、一覧領域だけへ `flex: 1` を与える。
- 見出し・操作部を含む固定高要素と一覧の矩形を実表示で測り、検索結果0件・少数・多数でも検索欄直下から一覧が始まることを確認する。
- `#add-dialog` のfieldsetへ `min-width: 0` と内部overflow境界を設定し、狭い高さでもツールバー・一覧がグループ枠外へ飛び出さないことを確認する。

### 2-17. Microsoft権限オンライン確認の状態説明

- 権限確認のローディング・成功・失敗を「オンライン確認」と明記する。
- 失敗表示には保存済み資格情報を変更していない旨を加え、通信失敗と再認可が必要なtoken拒否の理由は維持する。
- フロント単体テストで失敗後も行が選択可能であることと、誤解防止文言を検証する。

### 2-18. CSV共通解析・プレビュー境界

- byte列の文字コード変換、改行正規化、区切り文字設定、上下読み飛ばし、ヘッダー処理を共通関数へ集約し、通常fetch・field_names・previewから利用する。
- プレビューIPCは秘密値を扱わずローカルパスと解析設定だけを受け取り、処理後の列名、先頭/末尾各10行、データ行数、実際に適用した解析条件を返す。
- UTF-8・Shift_JIS、CRLF・LF・CR、各区切り文字、上下読み飛ばし、先頭末尾重複除去をRust単体テストで検証する。

### 2-19. CSV即時プレビューUI

- CSVフォーム下部へ状態表示とスクロール可能な先頭/末尾テーブルを追加する。
- パス選択・入力、各select、数値、checkbox変更をデバウンスし、古い非同期応答はsequence番号で破棄する。
- 未入力・解析中・成功・失敗を同じ領域へ表示し、ダイアログの既存スクロール境界を維持する。

### 2-20. Notionデータベース名の動的取得・保存

- NotionのデータベースID取得APIをcredential ID / 保存済みsourceの双方から呼べるIPC境界へ追加する。
- `database_name` を非秘密設定として追加し、一覧選択時は既に取得したタイトルを即時反映、URL・ID入力と既存編集時はID APIで最新化する。
- `deriveDefaultName` は保存済み名称をID短縮表記より優先する。最新名が取得できない場合は保存値、手動表示名、既存IDを維持する。

### 2-21. 統合検証・文書同期

- frontend / Rustの全品質ゲート、CSV実ファイルの実表示、Notionオフライン境界テストを実行する。
- NotionライブAPIは資格情報が必要なため当初は実テナント確認待ちとして記録し、その後の利用者確認結果を6-2へ追記する。

### 2-22. Notion完成仕様へのUI・状態管理リファクタリング

- Notionの一覧選択ボタンを `renderAutoSetupRow` のURL入力ボタン隣へ統合し、独立 `browse-area` へ重複表示しない。
- Notionの `database_name` と接続先表示名を読み取り専用にし、一覧選択・ID/URL解決成功時は共通関数から両方へ最新名を反映する。
- 名称同期処理を「取得開始」「成功」「失敗」の状態へ分離し、失敗時はフォーム値を変更せず、画面内状態表示だけを更新する。
- 旧 `shouldUpdateNotionDisplayName` と手動名保護テストを廃止し、既存の手動表示名も成功時に上書きする回帰テストへ置き換える。

### 2-23. Notion再読み込み同期・文書・完成検証

- 保存・再読み込み経路で、保存済み `database_name` と表示名が最新名へ同期される境界を追加する。API失敗時は保存済み値を維持する。

### 2-24. Microsoft系接続先の Entra ID / Microsoft 365 分類

- source type の永続IDと大分類 `microsoft` は維持し、chooser専用の表示グループ定義で Entra ID と Microsoft 365 を分離する。
- Entra ID はユーザー、グループ、デバイス、Intuneデバイス、ライセンスの5種を固定順で表示する。
- Microsoft 365 は Teams、SharePointリスト、ドキュメントライブラリ、Outlook、OneDrive（組織・個人）、Teams タスク & Planner の7種を既存manifest順で表示する。
- 項目名の `EntraID` はmanifestとフォーム定義の双方で `Entra ID` へ統一し、両者の整合テストを維持する。

### 2-25. Entra ID系5種の委任OAuth

- capabilityを `directory_users`、`directory_groups`、`directory_devices`、`intune_devices`、`licenses` に分け、それぞれ `User.Read.All`、`Group.Read.All`、`Device.Read.All`、`DeviceManagementManagedDevices.Read.All`、`LicenseAssignment.Read.All` を要求する。
- manifestで対象5種の `credentialAuthMethods` に `delegated` を追加し、対応capabilityを1種ずつ宣言する。フロントの選択可否とRustの保存・解決・再読み込み境界は同じ宣言に対応させる。
- 既存のGraph connectorはaccess tokenを共通利用しているためエンドポイントと列定義を維持し、認証方式の許可境界だけを拡張する。
- 既存delegated資格情報はSharePoint capabilityとして扱う後方互換を維持し、新capability利用時は再認可を必須にする。
- 組織アカウント専用、管理者同意、Entra / Intune ロール、Intuneライセンスの条件を利用ガイドへ記載する。

## 4. 実装で判明した追加対応

- フェーズ2では、ピッカーの認証方式判定もアクセストークンの有無ではなく明示的な `auth_method` へ変更した。これにより空トークンや将来の認証方式追加で誤った endpoint を選ばない。
- Graph互換性判定を `credentials.rs` に集約し、ソース保存・更新、資格情報更新、preview、reload、SharePointブラウズから同じ判定を利用する。
- フェーズ17のエラー配色を実環境のIPCまで追跡すると、`ServiceError::external` が内部原因を汎用文へ丸めていた。秘密値や生のレスポンスを露出せず、通信失敗・トークン発行拒否・claim解析失敗・設定不足へ分類した利用者向け理由を返すよう補完した。
- Rust全テストはファイルシステムサンドボックス内ではWindows DPAPIが `0x80070002` を返すため、通常ユーザーコンテキストで再実行した。新規テストを含む全テストが成功し、失敗は実装回帰ではなく実行環境の制約であることを確認した。
