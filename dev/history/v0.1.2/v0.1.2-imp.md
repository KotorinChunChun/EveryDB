# EveryDB 0.1.2 セキュリティ点検・修正計画

2026-10-19。依頼原文: 「本ツールから公開しているプログラム全てを総点検してセキュリティリスクや機密情報を排除してください。」全体の要求・台帳は親のdev/history/v0.1.7を正本とする。

- [x] calamine 0.37、zip 9.0.5、テスト用rust_xlsxwriter 0.100へ更新。ZIP3版の計9指摘を解消。mysql 28.0.4経由のlru 0.18.5とevent-listener 5.4.2で修正可能なunsoundも解消。
- [x] Vitest 4.1.11と互換範囲の推移依存へ更新。npm開発依存6指摘を0、製品用も0。npm10のpeer resolver不具合は隔離したnpm11.6.4でlockを再生成し、ignore-scriptsで再現した。
- [x] 実読取り256MiB、ZIP4096項目、CSV100万行の上限を追加。15万行の正規入力を保持。HTTPエラーから応答本文・URL生値を除外。Excel自前XMLも容量を制限。
- [x] 全品質ゲート成功。Vitest40ファイル151件、Rust214件成功／外部・実機16件ignore、fmt・clippy -D warnings・文書・CSP・製品ビルド成功。Rust最低版を依存に必要な1.88へ更新し、当該MSRVで有効になった既存Clippy警告1か所も修正。

RustSec DB 999ec89d5d3f10f20be14750ec8c2d8b44e0ac9b。vulnerability0、残るunsoundはWindowsの依存木にないglib 0.18.5の1件。保守終了9件はTauri推移依存等として残し、隠していない。yankedの照合・ネイティブライブラリ全CVE・外部サービス受入は未実施。ZIPの自前処理はファイルシステムへのextractを使用しないが、依存の修正版更新と資源制限を別に実施した。

通常DB・設定・開発用秘密保管先は読まない。旧版配布の撤回・新規公開・実導入は別途確認する。外部サービス認証とHelloなど従来の未受入範囲を合格へ変更しない。

最終結果: Cargo.lockの649 packageを保持し、上記3 packageの版・checksumとwebpki-roots旧wrapperの参照1か所だけを更新した。通常のcargo updateが併せて変更したerrno/rustix/winapi-util/tempfileの依存参照は今回採用せず、元の解決を保持した最小候補で再検証した。

- Windows既定featureの依存木は`cargo tree --locked --offline`で成功。rustls-webpkiはureqのTLS、ctutilsはpostgres-protocolの暗号依存経由で選択される。
- 最小候補でRust全230件中214件成功、0件失敗、16件ignore。`cargo build --locked --bin everydb`も成功。最初の試行も成功したが件数は合算しない。
- 更新後の3 package・版をOSVで再照合し、該当公告なし。これは全lockの保守終了通知や他OS問題の消滅を意味しない。
- UIとフロントエンドは変更しておらず、GUI/外部DB/ODBC/Windows Hello等の受入は未実施。インストーラ生成・配布・導入・サービス変更なし。
