# EveryDB v0.1.2 候補 フロントエンドのリファクタリング

作成日：2026-10-24。状態：実装・自動検証完了、実機確認未実施。ブランチ：refactor/source-editor-fields（main 5bd9f5a から分岐、未push）。製品版は0.1.1のまま変更していない。

## 0. 方針

利用者から範囲を限定しないリファクタリングの依頼を受けた。v0.0.5 の全面リファクタリング（[実装報告](../v0.0.5/v0.0.5-refact-imp.md)）で品質ゲート・共有 manifest・層分割は整備済みのため、残っている重複の大きいフロントエンドの接続設定まわりに対象を絞った。

- 挙動を変えない構造変更（refactor）と、途中で見つけた不具合修正（fix）を別コミットにする。
- Rust のコネクタ分割は [将来案](../../roadmap/PLAN_IDEAS.md) の「新規コネクタ追加が決まった時点で始める」に従い、今回は対象外とする。
- 変更前に、全34種別のテーブル設定ダイアログ・接続先ダイアログの描画 DOM とボタン配線、および各ピッカーの表示・呼び出しをスナップショットへ記録する一時的な特性テストを作り、各フェーズ後に一致を確認する。特性テストは確認用でありコミットしない。

## 1. フェーズ

- [x] R-P1：`field-renderer.ts` に `buildFieldActionRow` と `credentialManagedKeysOf` を設け、`dialog.ts` と `renderFieldsInto` で重複していた参照・一覧選択・取得ページ・リンクボタンの生成とトークン管理対象キーの算出を共通化する。コミット fe7adb5。
- [x] R-P2：`dialog.ts` 内の `fd-<key>` 要素の取得・値設定、保存済みトークンの credential ID 判定、Notion 名称取得タイマーの解除をヘルパーへまとめ、URL 自動入力を抽出値とフィールドキーの対応表で反映する形にする。コミット 666a041。
- [x] R-P3：`pickers/index.ts` の単一選択ピッカー7種（Notion、ブラウザプロファイル、Excel シート・テーブル、Airtable Base・テーブル・ビュー）を `openListPicker` へ集約し、Airtable の接続情報決定、閉じるボタン、全選択・解除、SharePoint のタブ切替も共通化する。コミット 42bac7d。

## 2. 判断

- `renderFieldsInto` へは、接続先ダイアログが従来から渡している Airtable の3ピッカーだけを明示的に渡す。呼び出し元が別のピッカーを持っていても、接続先ダイアログにボタンが増えないようにするため。
- 保存済みトークンの選択ウィジェットは参照ボタンより先に行へ組み込む。従来は2つのダイアログで順序が異なったが、両方を持つフィールドは存在せず、特性テストで描画結果が同一であることを確認した。
- Notion 名称の問い合わせは、編集中のソース ID がある場合はソース設定経由、無い場合は保存済みトークン経由とした。追加時にトークン未選択ならエラーを表示する挙動は従来どおり。
