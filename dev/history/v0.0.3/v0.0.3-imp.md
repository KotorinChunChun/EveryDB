### 0-2. Notion「データベース一覧が取得できない」の原因（実測で切り分け済み）

提供されたトークンで既存の live テストを実行した結果:

```
cargo test --lib notion_live_list_databases -- --ignored --nocapture
→ notion databases = 2 / test ... ok
```

**バックエンド（`browse::notion_list_databases`）は正常に動作している。**
したがって原因はフロント側にあり、コードを追うと次の経路で確実に失敗する。

1. 接続設定ダイアログ（`#parent-dialog`）は `get_source_detail` の結果を prefill する
   （[main.ts:1639](../../src/main.ts:1639)）。
2. `get_source_detail` は**マスターパスワードが未解錠のとき、秘密フィールドを
   `••••••••`（`SECRET_PLACEHOLDER`）でマスクして返す**（[commands.rs:124](../../src-tauri/src/commands.rs:124)）。
3. 「テーブルの追加/削除…」は入力欄の**現在値をそのまま** `browse_notion_databases` へ渡す
   （[main.ts:1738](../../src/main.ts:1738)）。
4. 結果、Notion へ `Bearer ••••••••` を送ることになり **401** で失敗する。

同じ問題は **SharePoint（`client_secret` がマスクされる）でも起きる**。
→ 対策は「秘密情報をフロントに出さず、バックエンドが保存済み設定を復号して一覧取得する」方式へ変更
（§2-6）。マスターパスワードの解錠状態に関係なく一覧が出せるようになる
（`preview_source_fields_by_id` と同じ考え方。DPAPI 復号はアプリ内部利用で、UI 表示ゲートとは独立）。

なお「取得はできるが 0 件」の場合はインテグレーションへの共有漏れであり、これは
アクセス許可設定ページを開くボタン + 説明文（§2-6）でカバーする。

## 2. 要件別・実装方針

### 2-1. 列見出しクリックでソート（昇順 / 降順 / 解除のトグル）

> 列見出しを左クリックしたら昇順または降順でソートできるようにして。この順序は再起動まで記憶する。
> クリックの度に昇順・降順・解除の３つの状態をトグルさせる。

| 項目 | 内容 |
| :--- | :--- |
| 状態 | `sortState: { column: string; dir: "asc" \| "desc" } \| null`（**モジュール変数＝セッション内保持**。「再起動まで記憶する」ため永続化はしない）。 |
| データ | 検索結果を `rawRows`（サーバー返却順）と `rows`（表示順）に分ける。ソート解除で `rawRows` の順序へ復帰する。`runSearch()` の直後にも現在のソートを再適用する（検索語や選択を変えても順序が維持される）。 |
| 対象列 | 「テーブル」「見出し」を含む全列。値は `cellText()` と同じ規則で取り出すため、疑似列も自然に並ぶ。 |
| 比較規則 | 両方が数値として解釈できれば数値比較、それ以外は `Intl.Collator("ja", { numeric: true })` で比較。**空値は方向に関わらず常に末尾**（昇順で空が先頭を占めて見づらくなるのを防ぐ）。 |
| トグル | 同じ列: なし → 昇順 → 降順 → なし。別の列をクリックしたらその列の昇順から開始。 |
| 表示 | 見出しラベルの後ろに `▲` / `▼` を出し、`title` に「クリックで降順 / 解除」等の次の状態を表示する。 |
| 既存機能との衝突 | ① **ドラッグ並べ替えとの同居**: ドラッグ操作では `click` が発火しないブラウザ挙動に依存せず、`dragstart` でフラグを立て `dragend` 直後の `click` を無視する。② **列幅リサイズハンドル**: ハンドル上の `click` は `stopPropagation()` して誤ソートを防ぐ（既に `mousedown` / `contextmenu` は止めてある）。③ 右クリックの列設定メニューは従来どおり。 |
| 副作用 | ソートで行の並びが変わるため、`selectedCell` は解除する。 |

### 2-2. テーブル追加ボタンの移設

> テーブル追加ボタンの位置をデータソース一覧の右上「管理」ボタンの左に変更

- ツールバーの `#add` を削除し、サイドバー見出し行（`.sidebar-title-row`）の
  **`#manage-toggle` の直前**へ移す。
- 240px の既定幅でも収まるよう、見出し行のボタンは `.manage-toggle` と同じ小型スタイルに統一し、
  ラベルは `＋追加`（`title` に従来の説明文）とする。
- **実測により「全選択 / 全解除」を絞り込み行へ移した**。当初は見出し行に 4 要素を並べたが、
  幅 240px では見出しの表示幅が 32px まで潰れて読めなくなったため
  （実測: タイトル 32px / bulk 72px / ＋追加 51px / 管理 40px）。移動後はタイトル 112px を確保。
  全選択・全解除は §2-4 で「絞り込みで見えているものだけ」を対象にするため、
  絞り込み欄と同じ行にある方が意味的にも自然。

### 2-3. 絞り込みボックスのクリアボタン

> データソースを絞り込みのボックスに何か入力されているとき、右端にバツボタンを置いて入力を消せるようにしてほしい。

- 入力欄を `.source-filter-row`（`position: relative`）で包み、右端に `×` ボタンを重ねる。
- **入力があるときだけ表示**（`hidden` を切り替え）。押下で値を空にし、`renderSources()` を呼び、
  フォーカスを入力欄へ戻す。ESC キーでも同じ動作にする。
- 入力欄には `padding-right` を確保し、テキストがボタンに潜り込まないようにする。

### 2-4. 全選択 / 全解除を絞り込み結果に限定

> 全選択や全解除のボタンですが、絞り込み中に行ったとき、検索結果で可視化されているテーブルのみに
> 対して変更を反映してほしい

- 現在の絞り込み条件に一致する行の判定は `renderSources()` 内のローカル関数 `match()` にあるため、
  これを **モジュールレベルの `visibleSources(): SourceInfo[]`** に切り出して共有する。
- 全選択: 可視テーブルの ID を**既存の選択に追加**（絞り込み外の選択は維持）。
- 全解除: 可視テーブルの ID だけを**選択から除去**（絞り込み外の選択は維持）。
- 絞り込みが空のときは従来どおり全件が対象になる（`visibleSources()` が全件を返すため）。
- ボタンの `title` を「（絞り込み中は表示中のテーブルのみ）」と補足する。

### 2-5. 接続設定画面へテーブル一覧をインライン化

> 接続設定画面で、テーブルの追加画面が独立しているが、接続設定画面の下部にリスト表示してほしい。

- 独立ダイアログ `#parent-table-picker` と `#parent-manage-tables` ボタンを廃止し、
  `#parent-dialog` の下部に `<fieldset>` として **テーブル一覧を常設**する。
- 構成: `全選択 / 全解除 / ⟳ 更新` のツールバー + チェックリスト + 説明文。
- **反映は「保存してリロード」に集約**（ユーザー回答）。保存時の処理順は
  ① 接続先ラベル保存 → ② 共有接続情報を配下テーブルへ反映 → ③ チェック差分の追加/削除 →
  ④ `loadSources()` + `runSearch()`。
  削除が発生する場合は保存直前に**確認ダイアログ**（既存 `confirmDelete()`）を挟む。
- 一覧取得は接続情報を編集した直後でも使えるよう、**ダイアログ上の現在値を優先**しつつ、
  秘密フィールドがマスクのままなら保存済みの値を使う（§2-6 の `_for_source` コマンド）。
- 一覧の取得に対応しない種別（PostgreSQL 等）は fieldset ごと非表示にする（従来と同じ判定
  `parentBrowseKind()`）。

### 2-6. Notion のデータベース一覧・アクセス許可設定ボタン・更新ボタン

> Notionの接続設定画面で、データベース一覧が取得できていない。APIからアクセス可能なデータベース
> 一覧を出して欲しい。また、データベースのアクセス許可を出すためのAPIの設定画面へすぐ飛べる
> ボタンがほしい。設定後DB一覧を取得する必要があるため、更新ボタンもほしい。

原因は §0-2 のとおり「マスクされた秘密情報をそのまま API へ渡していた」こと。

| 対応 | 内容 |
| :--- | :--- |
| 一覧の修正 | Rust に `browse_notion_databases_for_source(id, token)` / `browse_graph_site_resources_for_source(id, site_url, auth...)` を追加。**渡された値が `SECRET_PLACEHOLDER` または空なら、保存済み設定を DPAPI 復号して使う**（既存 `merge_preserving_placeholder` と同じ意味論）。フロントは秘密情報を持たなくてよくなる。 |
| アクセス許可設定ボタン | Notion のインテグレーション設定ページ `https://www.notion.so/my-integrations` を `open_ref` で開く。ボタン名は「アクセス許可を設定…」、`title` で「Notion 側で対象データベースをこのインテグレーションに接続してください」と補足。 |
| 更新ボタン | テーブル一覧ツールバーの `⟳ 更新`（§2-5 と共通）。押下で再取得する。 |
| 0 件のときの説明 | 「アクセス可能なデータベースがありません」に加え、**Notion 側でデータベースを開き `…` → 「接続」からこのインテグレーションを追加する**旨と、上記ボタンへの誘導を出す。 |

### 2-9. Microsoft 365 の利用可能テーブル一覧

> Microsoft365の接続設定画面でも、他のDBと同じように使用可能なテーブル（仕様として組み込んだ
> 各種）の一覧を表示してワンクリックで追加できるようにして。

- 接続先種別 `graph365`（parent = `Microsoft 365`）に対する `parentBrowseKind()` として
  **`graph365` を追加**し、§2-5 のインライン一覧をそのまま流用する。
- 一覧は API 取得ではなく **`TYPE_DEFS` から静的に構築**する。認証情報（tenant/client/secret）
  だけで使える次の 6 種別をチェックリストに出す:
  `graph_entra_users` / `graph_entra_groups` / `graph_entra_devices` /
  `graph_intune_devices` / `graph_licenses` / `graph_teams`
- **追加パラメータが必要な種別**（`graph_calendar` の対象ユーザー、`graph_onedrive` の対象ユーザー、
  `graph_planner` のグループ ID、SharePoint 系のサイト URL）は、ワンクリック追加にできないため
  一覧には出さず、「これらはテーブル追加ダイアログから個別に追加してください」と注記する。
- 既存テーブルとの対応付けは `type_` で行う（ファイル系の `table` 名に相当）。
  チェック済み = 追加済み、外す = 削除（保存時に一括反映）。

## 4. 実装で判明した追加対応

計画時に想定していなかった点を 3 つ追加で対処した。

### 4-1. 見出し行に 4 要素は入らない（§2-2）

幅 240px のサイドバーで「見出し + 全選択/全解除 + ＋追加 + 管理」を並べると、見出しの表示幅が
**32px** まで潰れた（実測）。全選択/全解除を絞り込み行へ移し、見出しは 112px を確保した。
全選択/全解除は §2-4 で絞り込み対象に限定するため、絞り込み欄と同じ行にある方が意味的にも自然。

### 4-2. テーブル追加時も秘密情報が平文で渡せない

一覧のチェックで**新しいテーブルを追加する**とき、共有の接続情報をフロントから渡すと
マスク値（`••••••••`）がそのまま保存され、壊れたソースができる。
`add_source_from_sibling`（[commands.rs](../../src-tauri/src/commands.rs)）を追加し、
**兄弟ソースの暗号化済み設定（`dpapi:` 付き）をそのままコピー**する方式にした。
`protect_config` は既に `dpapi:` が付いた値を二重暗号化しないため、この受け渡しで復号可能な状態を保てる。

### 4-3. 追加と削除の順序

保存時に削除を先に行うと、接続情報の引き継ぎ元（`children[0]`）自体が削除対象のときに
参照できなくなる。**追加 → 削除**の順に固定した。
