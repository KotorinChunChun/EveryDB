# v0.0.5-req EveryDB 要求仕様書

## 実装済

- テーブル追加画面で表示名にフォーカスがあるときにEnterキーを押すと、まるでキャンセルされたかのように閉じられてしまう。未入力時は接続先のデータソースのファイル名などを自動的に入力して確認の上、登録できるようにしてください。
- 接続先のファイルまたはテーブルを選んで、対象となるテーブルが確定したとき、自動的に後半の列の一覧表を再読込してください。
- データソースが追加されたとき、既定で表示がOFFですが、既定はONにしてください。

- ポケモンの日本語のデータベースを取得して追加できるようにしたい。PokeAPIから全データを一度に引き抜いてローカルにキャッシュすること。

- データソース左下で右クリックしたとき、メニューの後半が画面外にはみ出してしまう。画面内に収まる位置に展開するようにして

- Excelのシートセル範囲を対象とするとき、取り込むセル範囲の指定方法が適切ではない。範囲は常に変動するため、先頭セル、末尾セルの２つを指定する。そして、それぞれ自動取得と手動設定を設ける。手動設定では単一セルを指定する。バリデーションチェックする。
- 先頭セルの自動取得では、オートフィルタの設定行、とある列のデータの先頭行、データ全体におけるいずれかの列の先頭行を採用する。これは取得優先順位の順番で書いている。
- 末尾セルの自動取得は、使用済み範囲UsedRange、とある列のデータ最終行、いずれかの列の最終行、オートフィルタ対象範囲のを採用する。これは取得優先順位の順番で書いている。
- シート名は既存のものを一覧表示して選べるようにしてください。

- テーブル設定編集でエラーが発生した際は、接続情報・ソース設定のアコーディオンを展開したままにすること。
- 先頭セル・末尾セルの入力欄および「表から選択」ボタンは、それぞれの手動指定コンボボックスのすぐ右隣に配置すること。
- 基準列の入力欄は「先頭セル用」と「末尾セル用」で個別に作成し、それぞれの自動取得コンボボックスの右隣に配置すること。カンマやコロンを用いた複数列指定（例: A:C, E）に対応すること。
- 「表から選択」画面では実際の10x10のサンプルデータを表示し、画面上からクリックでセル・列を選べるようにすること。
- 表示するサンプルデータの位置は以下のように動的に切り替えること。
- 先頭セル指定時：表の上から10行分（左上）
- 末尾セル（自動・基準列）指定時：最終行の先頭列から10x10（左下）
- 末尾セル（手動）指定時：最終行の最終列から10x10（右下）
- 選択画面では「Ctrlキーでの複数選択」「ドラッグでの範囲選択」を可能にし、画面上にその操作ヒントを表示すること。
- 選択画面を再度開いた際、すでに入力されている選択状態を画面上に自動復元すること。
- 選択画面の表の見出しが「B2」からスタートしてしまう表示ズレを修正し、「A1」から正確に描画すること。
- テーブル設定編集の「一覧から選択」時に発生するパス解決エラーを修正し、親ツリーに設定されたExcelブックのファイルパスを確実に取得すること。
- 大容量データの列一覧取得時の遅延を解消するため、全データ行のパースをやめ、ヘッダー行1行のみをピンポイントで読み込んで高速化すること。
- 実際のデータ読み込み時の末尾セル検出において、UsedRange全体を誤って読み込むバグを修正し、「指定した基準列のいずれかが空欄ではない最終行」を最優先で検索・特定すること（下からの逆順走査および空文字列の無視を実装すること）。
- Excel ListObject のテーブル設定編集で、リストからテーブルを選べるようにすること。
- データソースの全展開、全折り畳み（良い名前が浮かばない）ボタンを追加して
- データソースの右クリックメニューにもエクスポートを追加して、選択テーブルのみのエクスポートをしてほしい。ついでに右上のボタン名もエクスポートに変える
- データソースの操作ガイドを追加する。ペインの右上に正方形の「？」ボタンを追加し、押したら利用可能なショートカットキー一覧を画面内ダイアログで表示する。
- 接続先をAltを押しながらクリックしても、他の接続先の表示が解除にならない不具合を修正する。
- Airtableテーブル追加時の入力支援機能（テーブルURLのコピー＆ペーストによるBaseID、テーブルID、ビューIDの自動設定）を追加する。
- 各種データソース（Google Sheets、Notion、SharePointサイト・リスト・ライブラリ、ファイル系等）におけるURLコピー＆ペースト・ドラッグ＆ドロップ自動入力支援機能を追加する。
- テーブルビューに最左端の固定システム行番号列（`#`）および「テーブル」列の右隣に独立した固定列（`元行`）を配置し、読み飛ばし位置を加味した元データ物理行番号を表示する。
- 検索上限行数、データソースのチェック選択状態、接続先グループの展開/折りたたみ状態を `localStorage` に保存・保持し、再起動時に自動復元する。
- データソース一覧の見出し部分（タイトル・操作ボタン・フィルタ欄）をスクロールしても常時表示されるよう固定化し、絞り込み検索ボックスを左端、操作ボタン群を右端に配置。
- 接続先グループ（ツリー親ノード）の右端に常時一括リロードボタン（`⟳`）を配置し、管理モード以外でもワンクリックで配下テーブルを一括再読込できるよう実装。
- リロード仕組みの調査結果および Drop Table 等による副作用検討を行い、FTS5 全文検索インデックス最適化 (`optimize`) コマンド自動発行による副作用のない高速化を実装。
- Airtable の設定画面において、ワークスペースページ (https://airtable.com/workspaces) を開けるリンクボタンを実装。
- Airtable を接続先ツリーの親（Base 単位）と子（Table / View 単位）に分離し、Personal Access Token を利用して実在する Base 一覧、Table 一覧、View 一覧を API 取得して選択できるピッカーモーダルを実装。
- Airtable の接続設定画面において、実際の接続に用いる ID (Base ID, テーブル ID, ビュー ID) と、キャプション (Base名, テーブル名, ビュー名) を対にして並べ、対応関係を明確化。また選択ピッカーやツリー一覧表示においてキャプション名を優先的に自動補完・表示する機能を実装。
- 過去に設定したことのあるトークンIDを再利用設定できるようにしてほしい。またトークン管理画面のようなものを作成し、追加・削除・置換を一括でできるようにして欲しい。
  → 実装済み。⚙設定→「🔑 保存済みトークンの管理…」から追加・置換（一括反映）・削除ができる
  （[`v0.0.5-imp.md`](./v0.0.5-imp.md) §7 参照）。

## 質問と回答（QA）

実装前に確認した論点と決定。

| #   | 質問 | 回答 | 関係する要求 |
| :-- | :--- | :--- | :----------- |
| 1   | リロードの仕組みはどうなっていますか？全データをリロードするとき、基本的に Drop Table などしたほうが高速にリロードできませんか？ | 現在は WAL モード＋単一トランザクション内で対象ソースの既存行を `DELETE` してプリペアドステートメントで再挿入する SQLite の最速置換パターンを採用。`records` は全ソース同居のマルチテナント構造のため `DROP TABLE` は他ソースデータ消失やエラー時スナップショット消失の重大な副作用がある。副作用のない高速化としてリロード完了後の FTS5 自動最適化 (`optimize`) を追加した。 | リロード高速化・検討 |
| 2   | 保存済みトークンを「置換」したとき、既にそのトークンを使っている既存ソースにはどう反映させますか？ | 共有参照方式。ソースは実際のトークン値を直接持たず「このトークンを使う」という参照だけを持つ。管理画面で値を書き換えれば、紐づく全ソースが自動的に新しい値で動くようになる（個別のソース編集は不要）。 | トークン管理画面 |
| 3   | 使用中（どこかのソースが参照している）の保存済みトークンを削除しようとしたらどうしますか？ | 削除をブロックし、使用中のソース一覧を表示する。先に別のトークンへ付け替えるか、それらのソースを削除してからでないと削除できない。 | トークン管理画面 |
| 4   | `v0.0.6` の既存未コミット変更をどう扱いますか？ | 既存作業として保持し、全品質ゲート後に機能単位の独立コミットとして固定する。 | リファクタリング残件・Phase 0 |
| 5   | 未保存browseのcredential秘密値をIPCへ渡さない境界はどうしますか？ | Rust側で保存済みcredentialを解決し、フロントは参照IDだけを保持する。 | RF-60-13 |
| 6   | `quick-xml` のhigh脆弱性2件をどう扱いますか？ | 0.41以上への更新を別コミットで行い、XML系回帰テストと監査を通す。 | RF-60-11 |
