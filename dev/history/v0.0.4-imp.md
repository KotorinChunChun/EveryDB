### 0-2. 実測で確認した外部データソースの仕様

**法人番号（国税庁 法人番号公表サイト）**

- 一覧ページ `https://www.houjin-bangou.nta.go.jp/download/zenken/index.html` は 3 つの形式セクション
  （`#csv-sjis` / `#csv-unicode` / `#xml-unicode`）を持ち、各セクション内に都道府県ごとの
  `<dt class="mb05">県名</dt>` と、直後の `<a onclick="return doDownload(ID);">` がある。
  同じ都道府県でも形式ごとに ID が異なる（月次更新のたびに ID も変わりうる）ため、**毎回ページを取得して
  「csv-unicode セクション内」から都道府県名に対応する ID を都度パースする**方式にした
  （ID のハードコードはサイト更新で即座に壊れるため避ける）。
- ダウンロードは `POST /download/zenken/index.html` に
  `jp.go.nta.houjin_bangou.framework.web.common.CNSFWTokenProcessor.request.token`（GET 時に埋め込まれる
  CSRF トークン）+ `selDlFileNo=<ID>` + `event=download` を送る。**GET でトークンを取得したのと同じ
  セッション（Cookie）で POST する必要がある**ため、`ureq` の Agent（cookies 機能）で GET→POST を
  同一セッションで行う（実測: Cookie を共有しない単発リクエストでは失敗する）。
- レスポンスは zip（`Content-Disposition` にファイル名）。中身は CSV 1 本 + `.asc`（署名、無視してよい）。
  実測（岐阜県）: 74,360 件、UTF-8（BOM なし）、30 列。列の対応は実データの値から逆引きで確認した
  （法人種別 101=国の機関の実例、都道府県コード 21=岐阜、郵便番号 7 桁等、英語表記・フリガナ列の並びが
  値と整合）。詳細は §2-6 のフィールド対応表を参照。

**郵便番号（日本郵便）**

- `https://www.post.japanpost.jp/service/search/zipcode/download/utf/zip/utf_ken_all.zip` は認証・トークン
  不要の直リンクで取得できる（実測 200 応答、2MB）。中身は `utf_ken_all.csv`（UTF-8、BOM なし、124,513 件、
  15 列 = 公開されている `KEN_ALL.CSV` の UTF-8 版と同一レイアウト）。

**WEB サイト（例: zenn.dev の検索結果）**

- `https://zenn.dev/search?q=vba` は Next.js の CSR ページで、**HTML 内に検索結果が 1 件も無い**
  （`<article>` 0 件、`__NEXT_DATA__` にも結果は含まれず `counts` のみ）。実際の結果は
  `https://zenn.dev/api/search?q=vba&source=articles` という JSON API から取得されている（実測で確認）。
  → 「ページの HTML をそのまま取り込む」単一方式では要求の具体例そのものが満たせないため、
  **HTML表 / CSS セレクタ / JSON API の 3 モード**を用意する（§2-8）。

## 2. 要件別・実装方針

### 2-1. 検索結果の右クリックメニューが閉じない不具合

> 検索結果の画面で右クリックしてメニューを出した後、他のセルをクリックしてもメニューが消えない。

**原因**: メニューを閉じる仕組みは `document.addEventListener("click", () => closeAllContextMenus())`
（[main.ts:896](../../src/main.ts:896)）だが、セルのクリックは `cell.onmousedown = () => selectCell(i, c)`
（[main.ts:1484](../../src/main.ts:1484)）で処理され、`selectCell` は同期的に `renderRows()` を呼んで
表示範囲のセル DOM を**丸ごと作り直す**（`rowsEl.innerHTML = ""` → 再構築）。その結果、
`mousedown` の時点でクリックされた `<div class="cell">` は `mouseup`/`click` が発火する前に
DOM から切り離され、`click` イベントが `document` まで伝播しない（切断済み要素からのイベントは
伝播しない）。これが「クリックしても閉じない」の直接原因。

**対応**: `selectCell()` の先頭で `closeAllContextMenus()` を呼ぶ。セル選択が変わる操作
（マウスクリック・矢印キー）は常にこの関数を通るため、経路を1箇所塞ぐだけで解決する。

### 2-2. 「保存してリロード」の読み込み中表示

> データソース追加において「保存してリロード」をおしたとき、画面がフリーズしてしまうため、
> 読み込み中であることを明示してほしい。

- 原因は「フリーズ」ではなく、`add_source`/`update_source` が内部で初回 fetch（`reload_one`）を
  同期的に行うため、リモート系（Notion/Graph/DB 等）で数百ms〜数秒かかる間、ボタンの見た目が
  変化せず「反応していない」ように見えること。
- `add-dialog` の保存ボタン（`value="ok"`）と、`parent-dialog` の `#parent-save` に、既存の
  `#reload-status`（`⚙ 設定` の「今すぐ全ソースを更新」で使っているスピナー）と同じ見た目の
  読み込み表示を追加する。保存中はボタン群を disabled にし、`保存中…（初回取得のため数秒かかる場合があります）`
  を表示する。完了/失敗で元に戻す。

### 2-3. TSV出力 → 出力ダイアログ（TSV/CSV/JSON + 文字コード）

> TSV出力 ボタンは 出力に変更して、ダイアログで複数の形式を選べるようにして。tsv、csv、jsonなど

- ツールバーの `#export`（現在ラベル「TSV出力」）のラベルを「出力」に変え、クリックで新規
  `#export-dialog` を開く。中身: 形式（TSV/CSV/JSON のラジオ）+ 文字コード（UTF-8(BOM付き)/UTF-8/Shift_JIS、
  JSON選択時は disabled 固定 UTF-8）+ 件数表示 + 「エクスポート」ボタン。
- 生成:
  - TSV: 既存の `tsvEscape`（タブ/改行を空白に置換）をそのまま流用。
  - CSV: 新規 `csvEscape`（カンマ・ダブルクオート・改行を含む場合は `"..."` で囲み、`"` は `""` に）。
  - JSON: `columns` をキーにしたオブジェクト配列を `JSON.stringify(_, null, 2)`。
- 文字コード変換: UTF-8 / UTF-8(BOM) はフロントで完結（`TextEncoder` + 先頭に `EF BB BF` を付与）。
  Shift_JIS はブラウザ標準 API でエンコードできないため、新規 Tauri コマンド
  `encode_shift_jis(text: String) -> Vec<u8>`（`encoding_rs::SHIFT_JIS.encode()`、既存依存で追加コストなし）
  を呼ぶ。書き込みは `writeTextFile` ではなく `@tauri-apps/plugin-fs` の `writeFile`（バイト列）に変更。
- 拡張子・フィルタ・既定ファイル名を形式ごとに切り替える（tsv/csv/json）。

### 2-4. ブラウザ対応表に Vivaldi 追加

> 各データソースの対応ブラウザにVivaldiも追加して（Chromium系です）

- `browser_history` / `browser_bookmarks`（既存）と、新設する `browser_downloads`（§2-5）の
  ブラウザ選択に `{ value: "vivaldi", label: "Vivaldi" }` を追加する。
- Rust 側は Chromium 系の分岐が `browser == "firefox"` 以外を一括で扱う実装のため、**コード変更は不要**
  （`vivaldi` は自動的に Chromium 分岐に入る）。プレースホルダーの例示パスのみ Vivaldi 用に追記する
  （`%LOCALAPPDATA%\Vivaldi\User Data\Default\History`）。

### 2-5. ブラウザのダウンロード履歴データソース

> ブラウザのダウンロード履歴をデータソースとして登録できるようにして

- 新規種別 `browser_downloads`。フィールドは `browser_history` と同じ構成（ブラウザ選択 + パス）で、
  Vivaldi を含む 5 択（Chrome/Edge/Brave/Vivaldi/Firefox）。
- Chromium 系: 履歴と同じ `History` ファイル内の `downloads` + `downloads_url_chains` テーブルを使う
  （履歴用の `copy_locked_sqlite`（ロック回避コピー）をそのまま再利用）。列: ファイル名(`target_path` の
  ファイル名部分) / 保存先パス / URL(`downloads_url_chains` の末尾) / 状態 / サイズ / 開始日時 / 完了日時。
  時刻は履歴と同じ WebKit エポックのため既存の `webkit_micros_to_unix_secs` を再利用する。
- Firefox: `places.sqlite` の `moz_annos`(`downloads/destinationFileURI`) を `moz_places` と結合して
  復元する（ブックマーク実装と同じ「簡易版」の考え方: フォルダ階層等は持たない）。
- `open_ref` 既定値はダウンロード先のローカルパス（クリックでファイルを直接開ける）。
- フロント: `PATH_GROUPED_TYPES` に `browser_downloads` を追加（履歴/ブックマークと同様、接続先は
  「パス」グルーピングにする）。

### 2-6. 法人番号 全件データのインポート

> 法人番号検索の任意の県の全データをインポートしたい（検証は「岐阜県」を使う）

- 新規種別 `corporate_number`。フィールド: `prefecture`（select、47都道府県+全国の48択）、
  `source`（select: `auto`=自動ダウンロード[既定] / `file`=手動でダウンロード済みの zip/csv を指定）、
  `path`（`source=file` のときだけ使う、参照ボタン付き）。
- `auto` 時の取得手順は §0-2 のとおり（GET でトークン取得 → csv-unicode セクションから都道府県名で
  ID を検索 → 同一セッションで POST → zip 応答をメモリ上で展開）。**サイト構造が変わると失敗する**ため、
  エラーメッセージに「サイト構造の変更、またはネットワーク要因です。`source` を『ファイル指定』にして
  手動でダウンロードした zip を指定してください」を含める。
- `file` 時は指定パスが `.zip` なら `zip` クレートで展開して中の `.csv` を1本だけ拾う
  （`.asc` 署名ファイルは無視）。`.csv` ならそのまま読む。
- CSV 列対応（実データの値から逆引き確認。§0-2）。全 30 列のうち意味のある 22 列を表示列にする
  （空になりがちな「画数」系や内部コード等は省く）:

  | 列位置 | 表示名                         |
  | :----- | :----------------------------- |
  | 2      | 法人番号                       |
  | 7      | 商号又は名称                   |
  | 9      | 法人種別                       |
  | 10     | 都道府県                       |
  | 11     | 市区町村                       |
  | 12     | 丁目番地等                     |
  | 16     | 郵便番号                       |
  | 5      | 更新年月日                     |
  | 18     | 法人番号指定年月日             |
  | 29     | フリガナ                       |
  | 25〜27 | 英語表記(名称/都道府県/所在地) |

  label 既定 = 商号又は名称、open_ref は無し（Webページ等の参照先が無いため）。

- 依存追加: `zip`（zip 展開）, `ureq` に `cookies` フィーチャを追加（CSRF トークンのセッション維持）。

### 2-7. 郵便番号データベースのインポート

### 2-8. WEBサイトの情報をデータソース化

> WEBサイトの情報をデータソースとして登録できるようにしたい。例えばgetクエリの検索結果
> https://zenn.dev/search?q=vba

- 新規種別 `web_page`。共通フィールド: `url`（GET先。クエリ込みの完全URL）、`mode`
  （select: `html_table` / `css_selector` / `json_api`）。モード別フィールドは常時表示し、
  プレースホルダーで「〇〇モード時のみ有効」を明記する（対象外モードでは無視される）:
  - `table_index`（number、`html_table` 用。既定 0 = 何番目の `<table>` か）
  - `has_header`（checkbox、`html_table` 用。既定 true = 先頭行を見出しにする）
  - `row_selector`（text、`css_selector` 用。1 行として扱う要素の CSS セレクタ）
  - `columns`（新設 FieldDef kind: `textarea`。`css_selector`/`json_api` 用。1 行に
    `表示名=セレクタ` または `表示名=JSONパス` を書く。`css_selector` は `セレクタ@属性名`
    でテキストの代わりに属性値（例: `URL=a@href`）を取れる。`json_api` で空欄なら各要素の
    トップレベルキーをそのまま列にする）
  - `json_root`（text、`json_api` 用。配列を取り出すドットパス。空欄 = レスポンス自体が配列）
- 実装は `scraper` クレート（CSS セレクタ + HTML パース）を新規依存として追加する
  （§0-2 のとおり `#csv-sjis` 的なページ内特定要素の抽出は法人番号連携では文字列検索で足りるが、
  汎用の「ユーザー指定 CSS セレクタ」は正式なセレクタエンジンが要る）。
- `html_table`: `table` セレクタで `table_index` 番目を取得 → `tr` を走査 → `has_header` なら
  先頭行の `th`/`td` を見出しに、以後の行を値に（列数不足は空文字埋め）。
- `css_selector`: `row_selector` で行要素を列挙 → 各行に対して `columns` のセレクタを
  **行要素を起点に**適用（該当なしは空文字）。
- `json_api`: レスポンスを JSON としてパースし、`json_root` で配列を取り出し、各要素に
  `columns` のドットパスを適用（またはトップレベルキーをそのまま展開）。
- 既定の `open_ref` は取得元 `url`（`label_column`/`open_ref_column` で上書き可能な既存の仕組みに乗る）。
- 取得先が JS 描画のみで実データを返さない場合はエラーメッセージで
  「このページは JavaScript で描画されており HTML に結果が含まれません。ブラウザの開発者ツールの
  Network タブで実際のデータ取得先 API を確認し、`json_api` モードで指定してください」と案内する
  （zenn.dev の実例で踏んだ問題そのものへの案内）。

### 2-9. ブラウザ系データソースのパス指定を「候補から選ぶだけ」に（実装後のフィードバックで追加）

> 接続先をブラウザにした場合に関して、いずれもデータベースの指定がとても難しい。自動で選択する
> 候補を検索して、その中から選ぶだけにできないか。

- `browser_history` / `browser_bookmarks` / `browser_downloads` のパス入力欄に
  **「候補から選択…」ボタン**を追加。押すと、選択中の「ブラウザ」に応じてインストール済みの
  プロファイルを自動検出し、一覧から選ぶだけでパスが埋まる（既存の「参照…」ボタンはファイルが
  分かっている上級者向けに残す）。
- 新規 Rust 関数 `browse::browse_browser_profiles(browser, target)`（`target` は
  `"history"`（閲覧履歴・ダウンロード履歴共通）/ `"bookmarks"`）:
  - **Chromium系（Chrome/Edge/Brave/Vivaldi）**: `%LOCALAPPDATA%\<ブラウザ>\User Data\` 直下の
    各プロファイルフォルダ（`Default`, `Profile 1`, …）を列挙し、対象ファイル（`History`/
    `Bookmarks`）が実在するものだけを候補にする。表示名は `User Data\Local State`（JSON）の
    `profile.info_cache.<フォルダ名>.name` を使う（取得できなければフォルダ名のまま）。
  - **Firefox**: `%APPDATA%\Mozilla\Firefox\profiles.ini` を最小限パースして各プロファイルの
    `Name`/`Path`/`IsRelative` を読み、`places.sqlite` が実在するものだけを候補にする
    （`profiles.ini` が読めない場合は `Profiles` ディレクトリを直接走査するフォールバックも用意）。
- 新規 Tauri コマンド `browse_browser_profiles`。
- 実機検証（このマシンの実際の Chrome/Edge プロファイル）: Chrome 18 プロファイル、
  Edge 7 プロファイルを正しく検出できることを確認済み（`cargo test --lib -- --ignored
browser_profiles_live --nocapture`）。
- 接続設定（親ノードの右クリック→接続設定）ダイアログ側は、共有フィールドが `path` のみで
  `browser` セレクトを表示しない構造のため、今回はスコープ外とした（対象は新規追加ダイアログのみ）。

## 4. 実装で判明した追加対応

計画時に想定していなかった点を 5 つ追加で対処した。

### 4-1. 「フリーズ」の根本原因はメインスレッドのブロック（§2-2）

当初は「スピナーを出すだけ」の想定だったが、`add_source`/`update_source` 等が同期 `fn` の
`#[tauri::command]` だと、初回 fetch（リモート通信を伴う）の間 **Tauri がメインスレッドで実行する**
ため、ウィンドウ全体が本当に応答しなくなることが分かった。単にスピナー要素を追加しても、
メインスレッドが塞がれていればスピナーの描画自体が止まってしまい意味がない。
そのため `add_source` / `update_source` / `add_source_from_sibling` / `delete_source` を
`async fn` 化し、Tauri の非同期ランタイム側のスレッドで実行されるようにした（内部処理は同期のまま
で構わない。スケジューリング先が変わるだけで十分）。

### 4-2. `method="dialog"` フォームの既定動作でダイアログが即座に閉じる（§2-2）

追加/編集ダイアログの保存ボタンは `<form method="dialog">` の submit ボタンだったため、
`e.preventDefault()` を呼ばない限り、JS の非同期処理が終わる前に**ブラウザの既定動作として
ダイアログが閉じてしまう**。保存中スピナーを表示する以前に、この既定動作を止める必要があった。
ついでに、バリデーション失敗時も同様に閉じてしまっていた（既存の軽微な不具合）ため、
`preventDefault()` の位置をバリデーションチェックより前に置き、無効な入力でもダイアログが
閉じないようにした。

### 4-3. `writeFile`（バイナリ）用の fs 権限が未許可だった（§2-3）

出力ダイアログの実装で `writeTextFile` から `writeFile`（`Uint8Array` 書き込み）へ切り替えたところ、
`capabilities/default.json` に `fs:allow-write-file` が含まれておらず、既存の
`fs:allow-write-text-file` だけでは書き込みが拒否される状態だった。権限を追加した。

### 4-4. 法人番号サイトのダウンロードには Cookie セッションの維持が必須（§2-6）

実機検証で、CSRF トークンを GET で取得した後、**同一セッション（Cookie）を維持したまま POST**
しないとダウンロードが失敗することを確認した。`ureq` の既定エージェントは Cookie を保持しないため、
`cookies` フィーチャを追加し `ureq::AgentBuilder` で 1 つの Agent を使い回す方式にした。

### 4-5. 法人番号 CSV の列対応は公式ドキュメントではなく実データの値から確認した（§0-2）

配布 CSV の列見出しが存在しない（無ヘッダー）ため、実際にダウンロードした岐阜県データの値
（法人種別コード `101`=国の機関の実例、都道府県コード `21`=岐阜、郵便番号 7 桁等）を手がかりに
列位置を逆引きで確認した。値同士の整合性（英語表記・フリガナの並びが元の値と対応する等）で
検証済みだが、**公式の列定義書と突き合わせたわけではない**点は申し送りとして残す（§7）。

## 7. 残件・申し送り

- **UI の実機（Tauri ネイティブウィンドウ）での通し操作は未実施。** 特に次の点は実際の画面で確認して
  ほしい:
  - 右クリックメニュー（グリッド/テーブル項目）を出した後、別セル・別項目をクリックして確実に閉じるか
  - 「保存してリロード」時にスピナーが表示され、保存完了までダイアログが閉じないか（Notion 等の
    リモート接続先で確認するとより体感しやすい）
  - 出力ダイアログで TSV/CSV/JSON × 3 文字コードの組み合わせが正しく書き出せるか
    （特に Shift_JIS で Excel が文字化けせずに開けるか）
  - WEBサイト種別の3モードの UI（テキストエリアの表示、プレースホルダー）
  - ブラウザ系データソース追加時の「候補から選択…」ボタン（一覧の表示・クリックでパスが
    埋まるか・複数プロファイルがある場合に見分けやすいか）
- `browser_downloads` のライブテスト（`browser_live_downloads`）は実機の Chrome/Edge プロファイルが
  必要なため未実行。`cargo test --lib -- --ignored browser_live` で確認できる。
- 法人番号 CSV の列対応（§4-5）は実データの値からの逆引き確認であり、**国税庁の公式列定義書
  （リソース定義書）との突き合わせはできていない**。列がずれていないかは、必要なら
  `https://www.houjin-bangou.nta.go.jp/pc/download/images/k-resource-dl.pdf` 等の公式資料と
  照らし合わせてほしい。
- 法人番号の自動ダウンロードは**サイトの HTML 構造に依存する**（`<dt class="mb05">県名</dt>` の
  直後に `doDownload(ID)` がある、という前提）。サイト改修で壊れた場合は `source` を
  「ファイル指定」に切り替えて手動ダウンロードした zip/csv を指定する経路で回避できる
  （手順書 [docs/guides/gov-data.md](../../docs/guides/gov-data.md) に記載）。
- `web_page` 種別は「取り込み方式」に関わらず全フィールドを常時表示している（モードに応じた
  条件付き表示は実装していない）。使わないフィールドは無視されるだけだが、UI 上の分かりやすさは
  プレースホルダーでの案内に留まる。
- ブラウザ系データソースの「候補から選択…」は**新規追加ダイアログのみ対応**。既存の接続先を
  右クリック→「接続設定」で開く親ダイアログには（`browser` セレクトを表示しない構造のため）
  実装していない。パスを後から変更したい場合は、テーブルを右クリック→「編集」から行う。
- `dev/` ディレクトリはリポジトリ全体で `.gitignore` 対象のため、本 `req.md`/`imp.md` はコミットに
  含まれていない（コード・ドキュメント(`docs/guides/`)側はすべてコミット済み）。
