## 4. 実装済みの Notion 完成仕様

### 「データベース一覧から選択」ボタンの配置

- 接続先追加画面にある「データベース一覧から選択」ボタンを、現在位置から「自動設定」ブロックへ移動する。
- 「自動入力」ボタンの右隣に配置する。
- 狭い画面でもブロック外へ飛び出さず、既存のダイアログ内スクロールと利用者リサイズを維持する。

### データベース名の同期仕様

- データベース名はユーザーによる入力・変更を禁止する。
- データベース名と接続先の表示名は、常に Notion 側から取得した最新名へ合わせる。
- データベース選択時、URL / ID 入力時、既存接続編集時、再読み込み時に、可能な範囲で Notion 側の最新名を取得して反映する。
- 最新名の取得に成功した場合は、以前の表示名が手動設定値であっても Notion 側の名前で更新する。
- 通信失敗時は空欄や ID 表示へ戻さず、最後に正常取得して保存したデータベース名と表示名を維持する。
- 通信失敗によって保存済み接続情報を消去・上書きしない。失敗状態は利用者に分かる形で表示する。

### 完了したライブ確認

- 実トークンと共有済みデータベースを使い、ID 選択時・URL/ID 入力時・既存接続編集時に最新名が表示されること。
- Notion 側でデータベース名を変更した後、再読み込みにより表示名も同じ名前へ更新されること。
- ユーザーがアプリ側でデータベース名を変更できないこと。
- 通信失敗時に最後に正常取得できたデータベース名と表示名が維持されること。

## 5. ライブ確認で問題が出た場合の切り分け

- Microsoft の権限表示失敗は「保存済み認証情報が消えた」ことを意味しない。まず画面に表示される分類が、通信失敗、トークン発行拒否、claim 解析失敗、設定不足のどれかを確認する。
- Microsoft 側で権限や capability を変更した場合、保存済み refresh token だけでは新しい同意内容にならないため再認可する。
- Notion 名称取得失敗時は、データベースが Integration に共有されているか、保存済みトークンが有効か、入力 ID が正しいかを確認する。
- 問題を再現したら、対象の資格情報種別、接続先種別、画面のエラー全文、操作手順を控える。トークンや API キーそのものは記録しない。
