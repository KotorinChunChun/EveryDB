# v0.0.6-req EveryDB 要求仕様書

## 実装済

- 「接続先・テーブルを追加」で、抽象的な接続先分類を経由せず、実装済みの全テーブル種別を直接選択できるようにする。CSV などトークン不要の単体テーブルと、OneDrive（組織・個人）の双方を明示し、既存 Microsoft 365 接続がある場合も対象指定が必要な OneDrive の追加画面へ進めること。
- Microsoft Graph の委任 OAuth で、SharePoint サイト選択時の Teams 一覧をサインインユーザー本人が直接参加しているチームから取得できるようにする。アプリケーション認証の既存動作は維持する。
- Microsoft Graph の保存済み資格情報について、データソース種別ごとに利用可能な認証方式と委任 capability を定義し、非対応の組み合わせを UI・保存・実行の各境界で拒否する。
- 委任 OAuth の要求権限を固定の全部入りにせず、SharePoint、本人の Outlook 予定表、本人の OneDrive の capability ごとに最小権限を選択して認可・再認可できるようにする。
- Outlook 予定表は、委任 OAuth の場合にサインインユーザー本人の予定表を `/me/events` から取得できるようにする。アプリケーション認証では従来どおり対象ユーザー UPN を利用する。
- OneDrive は、委任 OAuth の場合にサインインユーザー本人のドライブを `/me/drive` から取得できるようにする。アプリケーション認証では従来どおり対象ユーザー UPN を利用する。
- 既存の app-only 資格情報・データソース・未指定 `auth_method` を後方互換で維持し、既存の委任 OAuth プロファイルは SharePoint capability として扱う。
- 利用者向け Microsoft 365 ガイド、委任 OAuth ガイド、開発計画を実装と一致させ、認証方式、必要権限、再認可、直接参加チームの制約、本人データの範囲を説明する。
- 自動テスト、全品質ゲート、可能な範囲の Microsoft 365 ライブ検証を実施し、未検証項目と必要な管理者設定を記録する。
- 保存済みトークンの種別を、既存 `graph` を利用する **Microsoft Entra ID（組織）** と、新規 scope を利用する **Microsoft アカウント（個人）** に分離する。既存資格情報の内部 ID、保存形式、認証方式、実行ロジックは変更せず組織用として維持する。
- 個人 Microsoft アカウント専用の保存済み資格情報を新設し、利用者が入力するクライアント ID、DPAPI で保護するリフレッシュトークンを保存する。テナント ID、クライアントシークレット、認証方式、capability の入力は持たせない。
- 個人 Microsoft アカウントの OAuth は Authorization Code + PKCE、固定 authority `consumers`、固定 scope `Files.Read` / `User.Read` / `offline_access` を使い、authorize と refresh の両方で同じ設定を使う。
- 既存の `graph_onedrive` は内部 ID と app-only / 委任 OAuth / UPN / `/me/drive` のロジックを変更せず、表示名だけ **OneDrive（組織）** に変更する。
- 個人 Microsoft アカウント専用の `microsoft_account_onedrive` データソースを **OneDrive（個人）** として追加し、対象 UPN を持たず、サインイン本人の `/me/drive` を起点に既存の読み取り専用再帰取得を利用する。
- 組織用と個人用の資格情報・OneDriveを UI、保存、実行の各境界で相互利用できないようにし、既存データは DB migration 無しで後方互換を維持する。
- Microsoft 365 ガイドへ組織用と個人用の違い、個人アカウント対応アプリの登録、必要権限、再認可を追記し、自動テスト・全品質ゲートを実施する。Microsoft 365 Personal のライブ検証はユーザー確認待ちとして記録する。
- Microsoft アカウント（個人）のOAuthクライアントIDは、本番用 `99728d09-e017-49b4-a922-55273167599f` をEveryDBへ固定で組み込む。利用者画面からクライアントID入力とEntra管理センターへの取得導線を除去し、authorize / refreshの両方で固定IDを使う。旧client IDで認可した個人用資格情報は同じプロファイルで一度だけ再認可し、DB migration無しで継続利用できるようにする。
- ブラウザのブックマーク等を保存してリロードした後や F5 リロード直後に、閉じたはずの接続先追加ダイアログが表示されたままになり、キャンセルでも消えない不具合を修正する。ブラウザ履歴・ブックマーク・ダウンロード履歴のパス項目ラベルは「プロファイル」に統一する。
- 「接続先・テーブルを追加」ダイアログの一覧表示領域を拡大し、先頭にインクリメンタルサーチを追加する。Microsoft 365 カテゴリでは EntraID のユーザー・グループ・デバイスを先頭へまとめる。
- Microsoft Entra ID（組織）および Microsoft アカウント（個人）の保存済みトークン一覧で、選択前に実際のアクセストークンへ付与された承認済みアクセス権限を表示する。一覧表示時に Microsoft へ通信して委任権限 `scp` またはアプリケーション権限 `roles` を確認し、通信失敗時は理由を表示するがトークン選択は妨げない。
- Airtable の Personal Access Token、Notion、Box は、公式 API から設定済み権限を完全取得できないため、今回の権限照会・表示対象外とする。
- 保存済みトークン管理の各プロファイルで、「使用中の接続先」をプロファイル選択行の外ではなく選択エリア内に表示する。
- ダーク／ナイトテーマで権限確認エラーが暗い背景の赤文字だけにならないよう、背景・文字・枠を組み合わせた読みやすいエラー表示へ変更する。承認済み権限の `roles` / `scp` 表記は、既存UIと同じ「アプリケーションの許可」「委任されたアクセス許可」に置き換える。
- Microsoft の委任認可時に、サインインしたアカウントの表示ID（メールまたはUPN）とMicrosoft側アカウントIDを資格情報へ保存し、認可状態欄で確認できるようにする。既存資格情報は再認可まで未記録と表示する。
- 「接続先・テーブルを追加」「SharePoint から選択」等の選択系ダイアログは、選択項目・絞り込み結果・画面遷移で外寸を自動変更しない。利用者によるリサイズを許可し、アプリウィンドウが小さくなった場合だけビューポート内へ収まるよう制約する。
- 固定外寸にした選択系ダイアログで、検索欄やそのラッパーが縦方向の余白を占有しないようにする。「接続先・テーブルを追加」は検索欄の直下から一覧を表示し、「SharePoint から選択」は検索欄を通常の入力欄の高さに保ったうえで一覧だけを残り領域へ伸ばす。外寸固定・利用者リサイズ・ビューポート追従は維持する。
- テーブル追加・編集ダイアログを狭くした場合も、グループボックス内の項目が枠外へ描画されないようにする。グループ内で必要に応じてスクロールし、ツールバーと一覧を同じ枠内に保持する。
- Microsoft 保存済み資格情報の権限確認はオンライン診断であること、失敗しても保存済み資格情報を削除・変更していないことを画面上で明示する。通信失敗とトークン発行拒否を区別し、従来の保存情報取得失敗と誤認させない。
- CSV ファイルの追加・編集画面で、解析後データの先頭10行と末尾10行を表形式でプレビューする。ファイルパス、文字コード、改行コード、区切り文字、先頭・末尾の読み飛ばし行数、ヘッダー有無を変更すると短い待機後に自動再解析し、設定結果・総行数・エラーを同じ画面へ表示する。
- CSV の文字コードは自動判定 / UTF-8 / Shift_JIS、改行コードは自動判定 / CRLF / LF / CR、区切り文字はカンマ / タブ / セミコロン / パイプから選択でき、保存後の通常取込とプレビューが同じ解析設定を使う。既存CSV設定は従来どおりUTF-8・カンマ区切りとして読み込めること。
- Notion データベースはIDとともにデータベース名を設定へ保存する。新規選択、URL・ID入力、既存設定の編集時にNotion APIから最新名を取得し、取得成功時は保存名と自動表示名へ反映する。通信失敗時は保存済み名を残し、利用者が手動設定した表示名は上書きしない。
- 利用者環境で Microsoft 365（組織）と Microsoft アカウント（個人）の認可、承認済みアクセス許可表示、OneDrive の初回取得・再読み込みが成功することを確認する。
- Notion 接続先追加画面の「データベース一覧から選択」ボタンを「自動設定」ブロックへ移し、「URLから自動入力」の右隣に配置する。狭い画面ではブロック内で折り返し、既存のダイアログ内スクロールと利用者リサイズを維持する。
- Notion のデータベース名と接続先表示名はユーザーによる入力・変更を禁止し、一覧選択、URL・ID入力、既存接続編集、再読み込みで取得できた Notion 側の最新名へ常に同期する。以前の表示名が手動設定値であっても、取得成功時は Notion 側の名前で更新する。
- Notion 名称取得の通信失敗時は、最後に正常取得して保存したデータベース名と表示名を維持し、保存済み接続情報を空欄・ID短縮名・種別既定名で消去または上書きしない。失敗状態は利用者に分かる形で表示する。
- 利用者環境で Notion の一覧選択、URL / ID入力、既存編集、再読み込み、名称編集禁止、通信失敗時の最後の成功名維持をライブ確認する。
- 「接続先・テーブルを追加」の Microsoft 系を **Entra ID** と **Microsoft 365** の2グループへ分割する。Entra ID にはユーザー一覧、グループ一覧、デバイス一覧、Intune デバイス一覧、Microsoft 365 ライセンス一覧を配置する。Microsoft 365 には Teams チーム一覧、SharePoint リスト、SharePoint ドキュメントライブラリ、Outlook 予定表、OneDrive（組織・個人）、Teams タスク & Planner を配置する。既存の `EntraID` 表記は `Entra ID` へ統一する。
- Entra ID ユーザー一覧、グループ一覧、デバイス一覧、Intune デバイス一覧、Microsoft 365 ライセンス一覧を、組織アカウントの委任 OAuth でも取得できるようにする。既存のアプリケーション認証は維持し、データソースごとの最小権限を capability として選択・認可・再認可できるようにする。管理者同意、サインインユーザーに必要な Entra / Intune のロール、Intuneライセンス条件を画面とガイドで説明し、個人Microsoftアカウントは対象外とする。
- ユーザーが改名・再編した Microsoft 365 ガイドを正本として、旧ファイル名への参照、実装と食い違う説明、文書間の重複を解消する。`microsoft365.md` は認証方式を選ぶ入口に絞り、「EveryDB での組織向け設定方法」「委任 OAuth の機能と権限」「注意事項」の詳細はアプリケーション認証・組織向け委任 OAuth・個人 OneDrive の各サブページへ統合する。実装側の手順書ルーティングと自動テストも改名後のファイル名へ同期する。
- v0.0.6 のバージョン整合と全品質ゲートを確認し、Windows向け MSI / NSIS インストーラを生成する。生成物のファイル名、サイズ、SHA-256、Authenticode署名状態を確認し、リリース記録へ残す。
