## v0.2 候補

### 更新処理

- 長時間 fetch の進捗、取消、部分成功を表示する。
- 先行する1コネクタで差分更新を設計する。削除、再同期、cursor/ETag の失効を扱えることを着手条件とする。
- ソース数100、行数100万でも更新中に検索できるロック設計を検討する。

### 検索

- `-term`、列フィルタ、ORなどの検索演算子。
- 日本語形態素と trigram の検索品質比較。
- 条件に合致したセルの強調表示。
- 事前に結果行数を表示する必要性と性能影響の検討。

### 保守性

- 新規コネクタ追加が決まった時点で、対象種別から1種別1ファイル化を始める。
- `app.ts` は行数ではなく、状態所有者、依存方向、公開関数、単体テスト可能性を基準に分割する。
- PostgreSQL / MySQL のテーブル一覧 browse。
- Google サービスアカウント JSON の安全な管理方法。

### 認証・Microsoft 365

- Teams / Planner の委任 OAuth は、第一優先ユーザーと実需要を確認してから着手する。
- シークレットのローテーション状態と利用元を表示する。

## 長期候補

- コンパイル時コネクタ SDK。任意 DLL の実行時読込は別のセキュリティ設計を必須とする。
- Windows 以外へ展開する場合の秘密値プロバイダ抽象。
- ローカルモデルによる自然言語から検索条件への変換。
- 利用者指定パスフレーズによる他 PC 向け暗号化設定エクスポート。
- macOS / Linux 調査。Access、IME、ブラウザプロファイル、Windows Hello の代替を先に列挙する。
- EveryDB 独自クラウド同期、モバイルは需要と運用主体が明確になった場合だけ再検討する。
- Google アナリティクス。
- Copilot チャットの質問履歴。
- 表示列名の LLM 自動設定。
- お気に入りの変換を IME 辞書へ登録する操作。

## 旧メモ（実装済みか再確認して整理）
