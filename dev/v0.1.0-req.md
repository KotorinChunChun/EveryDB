# EveryDB v0.1.0 要求仕様書

作成日: 2026-08-30  
状態: 実装中  
対応計画: [v0.1.0-imp.md](v0.1.0-imp.md)  
進捗管理: [v0.1.0-task.md](v0.1.0-task.md)

## 目的

v0.1.0 を「Windows 利用者へ渡し、初回起動から検索・復旧・更新を説明できる版」とする。新しい接続先を増やす前に、既存機能の信頼性、検索性能、初回体験、配布手順を整える。

ローカルファースト、Windows 10 / 11、既存の Vanilla TypeScript UI、リポジトリ内 Rust コネクタを維持する。

## 実装済

- [REQ-001] 開発計画の正本をグローバル規則に合わせ、現行版を `dev/v0.1.0-req.md`、`dev/v0.1.0-imp.md`、`dev/v0.1.0-task.md` に配置する。旧版は `dev/history/`、未確定案は `dev/PLAN_IDEAS.md` へ分離する。
- [REQ-002] v0.1.0 では静的 HTML の存在確認だけを行う Playwright を採用せず、既存の Vitest、Rust テスト、実機リリース確認を使う方針とする。

### REQ-010 CI 品質ゲート

- GitHub Actions の Windows ジョブで `npm ci` と `npm run check:all` を順に実行する。
- frontend と Rust を最初から別ジョブへ分けず、Tauri が必要とする `dist/` を同じジョブ内で生成する。
- live 接続、Windows Hello、インストーラ操作は CI へ含めない。
- CI が成功しない状態では v0.1.0 をリリースしない。
- 実装結果: `.github/workflows/offline-check.yml` に単一 Windows ジョブを追加した。ローカルで同一の `npm ci` 済み依存環境と `npm run check:all` の成功を確認した。GitHub 上の初回実行は push 後に確認する。

### REQ-020 トレイ常駐中の定期更新

- メインウィンドウの×ボタンでトレイへ格納しても、定期更新スケジューラを停止しない。
- ウィンドウを閉じたときの OAuth 取消と、プロセス終了時のスケジューラ停止を別処理にする。
- トレイ格納後にホットキーで再表示しても、定期更新が継続していることを確認する。
- 実装結果: OAuth 取消専用処理とプロセス終了処理を分離し、単体テストでトレイ格納経路が停止フラグを変更しないことを確認した。実機のトレイ・ホットキー操作はリリース人手確認へ集約する。

## 未実装

### REQ-030 複数語検索

- 空白区切りの AND 検索という利用者向け挙動と既存 IPC を維持する。
- 3 文字以上の語は FTS5 trigram、1～2 文字の語は LIKE を使用する。
- 複数語では FTS と LIKE を必要に応じて組み合わせ、全語 LIKE による全表走査を避ける。
- FTS 用の入力は構文として解釈させず、安全なフレーズとして渡す。
- 半角スペース区切りを v0.1.0 の互換仕様とし、全角空白・タブ対応は別要求とする。
- 「東京都 営業部」のような 3 文字以上同士と、「東京 営業部」のような短語混在を別々にテストする。

### REQ-040 利用者・開発文書の同期

- README の対応データソース数を、画面から追加できる 35 種類に合わせる。
- user-guide に検索履歴、検索プリセット、自動更新間隔を追記する。
- architecture とデータソース追加テンプレートに残る旧ファイル・旧識別子への参照を修正する。
- `excel_cell` はレガシー互換で再読込可能、新規追加不可、代替は `excel_range` と説明する。

### REQ-050 空状態とサンプル導線

- ソースが 0 件のとき、アプリの目的と「サンプルで試す」「接続先を追加」をメイン領域に表示する。
- 初回モーダルは必須とせず、操作を妨げない空状態を正本とする。
- 新しい架空データを重複作成せず、Git 管理済みの `samples/customers.csv` を配布リソースとして再利用する。
- `add_source` が初回取得まで行う既存仕様を利用し、直後に同じソースを二重 reload しない。
- サンプル取得に失敗した場合は成功扱いにせず、空状態に回復手順を表示する。

### REQ-060 バックアップと復元

- 設定画面からアプリ DB の整合したバックアップを保存できる。
- エクスポートは SQLite のバックアップ API 等を使い、WAL checkpoint 後の単純なファイルコピーを正本にしない。
- 秘密値は DPAPI 暗号文のまま保持し、他 PC・他 Windows ユーザーでは再認可が必要になり得ることを表示する。
- 復元元は一時領域で形式と schema version を検証する。
- 動作中の Connection をその場で差し替えず、復元をステージしてアプリ再起動時に原子的に入れ替える。
- 置換前の DB を退避し、置換または再オープンに失敗した場合は元へ戻す。`-wal` / `-shm` も復元設計の対象とする。

### REQ-070 v0.1.0 リリース

- 版番号は `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`src-tauri/tauri.conf.json` で一致させる。
- `npm run check:all`、依存脆弱性監査、クリーン Windows でのインストール、トレイ、ホットキー、バックアップ、アンインストールを確認する。
- リリース前に利用条件、配布先、コード署名の有無を決定し、署名なしの場合は配布上の注意を明記する。
- コード署名と自動更新は別項目として判断し、自動更新を v0.1.0 の必須条件にしない。

### REQ-080 excel_cell の新規追加拒否

- UI 非表示だけに依存せず、サービス層でも `excel_cell` の新規追加を拒否する。
- 既存 DB にある `excel_cell` の再読込は維持する。
- 本項目は防御的改善であり、v0.1.0 リリースの必須依存にはしない。
