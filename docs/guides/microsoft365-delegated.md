# Microsoft 365（Graph API・ユーザー委任）の接続手順

対象の EveryDB 種別: **SharePoint リスト / ドキュメントライブラリ**

> 本ファイルは **ユーザー委任（Delegated）** の個別手順です。
> 方式の比較と選び方は [Microsoft Graph 接続方法の選択](microsoft365.md)、
> app-only方式は [アプリケーション認証の接続手順](microsoft365-app-only.md) を参照してください。

## 概要

Microsoft Entra ID（旧 Azure AD）に **パブリッククライアント**としてアプリを登録し、
EveryDB から **「Microsoft にログインして認可…」** でブラウザ認可を行います。
取得したトークンは **ログインしたユーザー本人がアクセスできる SharePoint サイト・リスト**
の範囲に限定されます（テナント全体への管理者同意が不要な場合が多いですが、
組織ポリシーによっては管理者の同意が必要なこともあります）。

| 方式 | 手順書 | 認証 | Entra の許可の種類 |
| :--- | :--- | :--- | :--- |
| アプリケーションの許可 | [個別手順](microsoft365-app-only.md) | クライアントシークレット | **アプリケーションの許可** |
| ユーザー委任（本手順） | 本ファイル | ブラウザでユーザーログイン | **委任されたアクセス許可** |

## 事前に必要なもの

- Microsoft 365 / Entra ID のユーザーアカウント（SharePoint サイトへのアクセス権があること）
- アプリ登録を作成できる権限（通常はユーザー自身で可能。テナントポリシーにより管理者のみの場合あり）
- 取り込みたい SharePoint サイトの URL

## 手順

### 1. Entra でアプリを登録する

1. [Entra 管理センターのアプリ登録](https://entra.microsoft.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade) を開きます。
2. **新規登録** を押し、名前（例: `EveryDB SharePoint`）を入力します。
3. **サポートされているアカウントの種類** は **「この組織ディレクトリのみ（単一テナント）」**
   を選びます（EveryDB v1 ではテナントごとに独自のアプリ登録を使います）。
4. **リダイレクト URI** を設定します。
   - プラットフォームで **「パブリック クライアント/ネイティブ（モバイル & デスクトップ）」**
     を選びます。
   - **Redirect URI** に `http://localhost:58914/graph-callback` を **1 文字も変えずに** 追加します
     （EveryDB がブラウザ認可の応答を受け取るために内部で使う固定 URI です。
     1 文字でも違うと `redirect_uri_mismatch` エラーになります）。
5. **登録** を押します。
6. 概要画面に表示される次の 2 つをコピーします。
   - **アプリケーション (クライアント) ID**
   - **ディレクトリ (テナント) ID**

### 2. 委任されたアクセス許可を追加する

1. 登録したアプリの左メニュー **API のアクセス許可** を開きます。
2. **アクセス許可の追加** → **Microsoft Graph** → **委任されたアクセス許可**
   から、次を追加します。

   | 許可 | 用途 |
   | :--- | :--- |
   | `Sites.Read.All` | ユーザーがアクセスできる SharePoint サイト・リストの読み取り |
   | `offline_access` | リフレッシュトークン（再ログインなしでの更新） |
   | `User.Read` | サインインしたユーザーの基本プロフィール |

3. テナントのポリシーにより **管理者の同意が必要** な場合があります。
   そのときは **「（テナント名）に管理者の同意を与えます」** を押し、
   状態が「付与されました」になることを確認してください。
   （委任 `Sites.Read.All` でも、組織によっては管理者同意が求められます。）

> **補足**: クライアントシークレットは **作成しません**（パブリッククライアントのため不要です）。
> **証明書とシークレット** メニューは開く必要がありません。

### 3. パブリック クライアント フローを有効にする

EveryDB の委任 OAuth（Authorization Code + PKCE）には、
アプリ登録で **パブリック クライアント フロー** を許可する設定が必要です。

1. 同じアプリ登録の左メニュー **「管理」** セクションで、
   **API のアクセス許可** の **上** にある次の項目を開きます。
   - 日本語 UI: **認証**
   - 英語表示の場合: **Authentication (Preview)**
   （**証明書とシークレット** と **API のアクセス許可** の **間** にあります。）
2. ページを下へスクロールし、**詳細設定**（英語 UI では **Advanced settings**）を探します。
3. **「パブリック クライアント フローを許可する」**
   （英語 UI では **Allow public client flows**）を **はい** / **Yes** にします。
4. 画面上部または下部の **保存**（**Save**）を押します。

> **メニューが見つからない場合**
> - 左メニューで **Entra ID** → **アプリの登録** から、対象アプリを開き直してください。
> - テナントによっては **認証** が **Authentication (Preview)** と英語表記のままです。
> - それでも項目が無い場合は **マニフェスト** を開き、
>   `"allowPublicClient": true` に編集して保存してください。

### 4. EveryDB で Graph プロファイルを作成・認可する

1. EveryDB の **設定** → **🔑 保存済みトークンの管理…** を開きます。
2. 種別 **Microsoft 365 (Graph)** のプロファイルを **新規作成** します。
3. 認証方式で **「委任 OAuth（Microsoft にログインして認可）」** を選びます。
4. 手順 1 でコピーした **テナント ID** と **クライアント ID** を入力します。
5. **🔗 Microsoft にログインして認可…** を押します。
   既定のブラウザが開くので、Microsoft アカウントでサインインし、表示された許可を承認します。
   成功すると EveryDB に自動的に戻ります（ブラウザのタブは閉じて構いません）。
6. **「✅ 認可済み」** の表示を確認して **保存** します。

認可後に得られるリフレッシュトークンは EveryDB 内で暗号化保存されます。
アクセストークンの有効期限が切れた場合、EveryDB が自動的に更新を試みます。
長期間未使用で失効した場合や、パスワード変更・管理者によるセッション失効後は、
手順 5 の認可をやり直してください。

### 5. SharePoint 接続を追加する

1. 接続設定画面で **SharePoint リスト** または **SharePoint ドキュメントライブラリ** を追加します。
2. 認証情報欄の **選択…** から、手順 4 で作成した Graph プロファイルを選びます。
3. **サイトURL** に取り込みたいサイトを入力します（例:
   `https://<テナント>.sharepoint.com/sites/<サイト名>`）。
   **サイト/チームから選択** ボタンから選ぶこともできます。
4. **保存してリロード** を押し、テーブルにデータが表示されることを確認します。

## 認可の取消・タイムアウト

- ブラウザ認可中に **取消** すると EveryDB は「Microsoft の認可をキャンセルしました」と表示し、
  トークンは保存されません。
- ブラウザを閉じたまま長時間待つと **タイムアウト** し、同様に保存されません。
- アプリを終了すると、進行中の Microsoft OAuth 待機は **自動取消** されます。
- コールバック URI は **`http://localhost:58914/graph-callback` 固定** です。
  Entra アプリ登録の Redirect URI と EveryDB 内部の待受ポートが一致している必要があります。

## EveryDB 側の入力項目

| 項目 | 入力する値 | 備考 |
| :--- | :--- | :--- |
| 認証方式 | 委任 OAuth | アプリケーションの許可（クライアントシークレット）とは別プロファイル |
| テナント ID | Entra アプリ概要のディレクトリ ID | |
| クライアント ID | Entra アプリ概要のアプリケーション ID | |
| Microsoft アカウントの認可 | （手動入力しません） | 「Microsoft にログインして認可…」の結果が保存されます |
| 保存済みトークンプロファイル | 上記を含む Graph プロファイル | SharePoint 接続では **選択…** で参照 |
| サイトURL（SharePoint） | `https://<テナント>.sharepoint.com/sites/<サイト名>` | サイト/チームから選択も可能 |

## よくあるエラーと対処

| 症状 | 原因 | 対処 |
| :--- | :--- | :--- |
| ブラウザに `redirect_uri_mismatch` | Redirect URI の未登録・入力ミス | Entra の Redirect URI が `http://localhost:58914/graph-callback` と完全一致しているか確認 |
| `AADSTS65001` / 同意が必要 | 委任権限へのユーザーまたは管理者同意が未完了 | Entra でアクセス許可を追加し、必要なら管理者の同意を実施。再度認可 |
| `AADSTS700016` | クライアント ID がテナントに存在しない | テナント ID とクライアント ID の対応を確認 |
| 認証メニューが見つからない | 一覧画面を見ている、または UI が英語表記 | アプリ登録を開き直す。**Authentication (Preview)**（認証）を選択。API のアクセス許可の直上 |
| パブリック クライアント設定が無い | 詳細設定までスクロールしていない | **認証** 画面の **詳細設定** → **Allow public client flows** を **Yes** |
| 「Microsoft の認可が完了していません」 | まだ認可していない、またはトークン失効 | トークン管理画面で対象プロファイルを開き、認可をやり直す |
| `403 Authorization_RequestDenied` | 権限不足、またはユーザーが対象サイトにアクセスできない | Entra の委任許可を確認。SharePoint サイトのメンバー権限を確認 |
| SharePoint で 0 件 | サイト URL の誤り、リストが空、権限不足 | サイト URL を「サイト/チームから選択」で入れ直す。ブラウザで同ユーザーがサイトを開けるか確認 |
| ローカルポートエラー | ポート 58914 が他アプリで使用中 | 該当アプリを終了するか、PC を再起動してから再試行 |
